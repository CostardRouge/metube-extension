# CI, releases and the website

Read before touching a workflow, `scripts/build.sh`, the release procedure or the website's deployment. The procedure itself is in the README ("Releasing", "Website").

## Decisions

- 2026-10-17 — **Versions follow C13: `CHANGELOG.md` is the source, `release.yml` makes the tags** (replaces "the tag is the version", #3). One SemVer version in `package.json` (version only, never shipped) and the same in `manifest.json`, held together by `tests/manifest.test.mjs`. `release.mjs` and the C13 part of `release.yml` are the portfolio's identical copies (from `tamalou`); this repo appends one step to `publish`: every Release `vX.Y.Z` lacking `metube-sender-X.Y.Z.zip` gets it, built by `scripts/build.sh` in a worktree of its own tag, with the `.sha256`. **Why in the same job**: a tag or Release made with `GITHUB_TOKEN` triggers no other workflow, so the old tag-triggered release would never fire again. **How to apply**: a release is a changelog section plus both versions bumped, merged to `main`; never a pushed tag. A backfilled Release published later by `second-brain` gets its zip on the next push to `main` or a "Run workflow". Build tests are not re-run there (CI ran them on the merge). Release notes are the changelog section only; the old install steps live in the README and the website.
- 2026-10-17 — **Started at 4.1.0 "Egret", birds in alphabetical order.** `v1`–`v4` were already published (2026-09-29 to 10-01) with Chrome's one-number versions, and he runs `4`; starting SemVer at 1.0.0 would have read as a downgrade in Chrome and on the Releases page. So `CHANGELOG.md` restates them as 1.0.0 Albatross … 4.0.0 Dove at the very commits of `v1`–`v4` (backfills), and 4.1.0 is what came after (MIT license in the zip, the fullscreen warning, the version on the settings page). The old `v1`–`v4` tags and Releases stay as they are; deleting them once the backfill exists is the owner's call. No pre-release: Chrome refuses `1.2.0-beta`.
- 2026-10-17 — **The version shows at the foot of the settings page**, read at run time from `chrome.runtime.getManifest()` (no build step: the manifest IS the build-time value, written into the zip by `build.sh`).
- 2026-09-29 — **The zip holds only what the browser loads**, plus `LICENSE` since 2026-10-17 (MIT asks for the notice in every copy) (`FILES` in `scripts/build.sh`), `manifest.json` at its root, so the same zip serves "Load unpacked" and the Chrome Web Store. CI keeps it 14 days as a plain `.zip` artifact (`archive: false`, not zipped twice) (#2).
- 2026-10-01 — **The website is `docs/`, plain files like the extension**, deployed by `pages.yml` when `docs/**` changes on `main`; its first run turned Pages on (`enablement: true`), so nothing was clicked in the settings (#7). Its download button reads the latest release from the GitHub API and falls back to `releases/latest`.
- 2026-10-08 — **Runners named `ubuntu-24.04`**, not `ubuntu-latest`, which moves to Ubuntu 26 from 2026-10-19: the OS move becomes a one-line choice. Actions on their Node 24 majors (#9).
- 2026-10-09 — **CI and releases run Node 24**, the Active LTS; the tests have no dependency and still pass on 22, so the README keeps "Node 22 or newer" (#10).
- 2026-10-19 — **The portfolio standard (`COMMON-PROJECT-SPEC.md` C14–C19 in `second-brain`, decided 2026-10-19) applied here.** C16: `.gitignore` names `.env`, `.env.*`, `.idea/`, `.vscode/` and `node_modules/` beside `dist/` and `.DS_Store`, although nothing here reads an environment or installs a package — it is what keeps a stray `npm i` or an IDE folder out of a commit, and a file of those kinds found *tracked* is reported (rule 1), never quietly avoided.

## Traps

- 2026-09-29 — **An unpacked extension's ID comes from its folder path.** Loading an update from another folder installs a second copy without the settings; the README and the release notes say to unzip over the same folder.
- 2026-09-29 — **Chrome's version format** is 1 to 4 integers from 0 to 65535 with no leading zeros; `1.0.0-beta`, `01.2` and `70000` are refused by `build.sh` before anything is built. The Web Store also refuses a version that is not higher than the last.
- 2026-10-17 — **`docs/` is published whole**, so nothing private or internal goes there; that is why the agent memory lives in `memory/`.
