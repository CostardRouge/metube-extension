# CI, releases and the website

Read before touching a workflow, `scripts/build.sh`, the release procedure or the website's deployment. The procedure itself is in the README ("Releasing", "Website").

## Decisions

- 2026-10-17 (rev. 2026-10-24) — **Versions follow C13: `CHANGELOG.md` is the source, `release.yml` makes the tags** (replaces "the tag is the version", #3). One SemVer version in `package.json` (version only, never shipped) and the same in `manifest.json`, held together by `tests/manifest.test.mjs`. `release.mjs` and the C13 part of `release.yml` are the portfolio's identical copies, taken with `registry.yml` from `second-brain/system/meta/common-project-spec/shared/` since 2026-10-24, never from another repo (their `check` jobs follow the `CI_RUNNER` variable, never set here: public); this repo appends one step to `publish`: every Release `vX.Y.Z` lacking `metube-sender-X.Y.Z.zip` gets it, built by `scripts/build.sh` in a worktree of its own tag, with the `.sha256`. **Why in the same job**: a tag or Release made with `GITHUB_TOKEN` triggers no other workflow, so the old tag-triggered release would never fire again. **How to apply**: a release is a changelog section plus both versions bumped, merged to `main`; never a pushed tag. A backfilled Release published later by `second-brain` gets its zip on the next push to `main` that touches `CHANGELOG.md` or `package.json` (`release.yml`'s `paths` filter since 2026-10-24), or a "Run workflow". Build tests are not re-run there (CI ran them on the merge). Release notes are the changelog section only; the old install steps live in the README and the website.
- 2026-10-17 — **Started at 4.1.0 "Egret", birds in alphabetical order.** `v1`–`v4` were already published (2026-09-29 to 10-01) with Chrome's one-number versions, and he runs `4`; starting SemVer at 1.0.0 would have read as a downgrade in Chrome and on the Releases page. So `CHANGELOG.md` restates them as 1.0.0 Albatross … 4.0.0 Dove at the very commits of `v1`–`v4` (backfills), and 4.1.0 is what came after (MIT license in the zip, the fullscreen warning, the version on the settings page). The old `v1`–`v4` tags and Releases stay as they are; deleting them once the backfill exists is the owner's call. No pre-release: Chrome refuses `1.2.0-beta`.
- 2026-10-17 — **The version shows at the foot of the settings page**, read at run time from `chrome.runtime.getManifest()` (no build step: the manifest IS the build-time value, written into the zip by `build.sh`).
- 2026-09-29 — **The zip holds only what the browser loads**, plus `LICENSE` since 2026-10-17 (MIT asks for the notice in every copy) (`FILES` in `scripts/build.sh`), `manifest.json` at its root, so the same zip serves "Load unpacked" and the Chrome Web Store. CI keeps it 14 days as a plain `.zip` artifact (`archive: false`, not zipped twice) (#2).
- 2026-10-01 — **The website is `docs/`, plain files like the extension**, deployed by `pages.yml` when `docs/**` changes on `main`; its first run turned Pages on (`enablement: true`), so nothing was clicked in the settings (#7). Its download button reads the latest release from the GitHub API and falls back to `releases/latest`.
- 2026-10-08 — **Runners named `ubuntu-24.04`**, not `ubuntu-latest`, which moves to Ubuntu 26 from 2026-10-19: the OS move becomes a one-line choice. Actions on their Node 24 majors (#9).
- 2026-10-09 (rev. 2026-10-24) — **CI runs the Node of `.nvmrc`, 26 since 2026-10-24** (the portfolio's C14 moved to 26 in `second-brain#121`; it was 24, the Active LTS, from #10). The move touched `.nvmrc` and the words only: no dependency, no `@types/node`, no image, and `ci.yml` already reads `node-version-file`. The tests have no dependency and still pass on 22, so the README and `CLAUDE.md` keep "Node 22 or newer". `release.yml` and `registry.yml` run the runner's own Node (no `setup-node`), and `registry.yml`'s Node 24 comment is about `github-script`'s runtime, not this repo's — both untouched.
- 2026-10-19 — **The portfolio standard (`COMMON-PROJECT-SPEC.md` C14–C19 in `second-brain`, decided 2026-10-19) applied here.** C16: `.gitignore` names `.env`, `.env.*`, `.idea/`, `.vscode/` and `node_modules/` beside `dist/` and `.DS_Store`, although nothing here reads an environment or installs a package — it is what keeps a stray `npm i` or an IDE folder out of a commit, and a file of those kinds found *tracked* is reported (rule 1), never quietly avoided. C14: `.nvmrc` = 24 (26 since 2026-10-24) and `ci.yml` reads it (`node-version-file`), the floor of 22 stays prose because `package.json` carries the version and nothing else — the one `engines` exception in the portfolio, written in `CLAUDE.md`'s Context. The linter is **Biome at an exact version through `npx --yes`** (`ci.yml`, `CLAUDE.md`, the README name the same one; no dependency, no script), with its recommended rules over the extension's own folders, `tests/` and `docs/*.js`, never `vendor/`; the formatter stays off (a repo-wide reformat is its own pull request). Biome 2.5 lints the HTML and CSS of those folders too: the first run found the pages' buttons without a `type` and decorative SVGs without `aria-hidden` (fixed), two `<label>`s whose `<select>` `menu-editor.js` inserts at run time and the `<video>` whose tracks `overlay.js` attaches (each suppressed with a `biome-ignore` comment saying why), and `style/noDescendingSpecificity` on `options/options.css` — turned off in `biome.json` (a JSON file cannot carry the reason, so here it is): the stylesheets are written top-down by component and reordering four rules by specificity would scatter them for nothing the cascade needs. C15: Dependabot raises the workflows' actions only. C11: the website ships the whole icon set from three committed SVG sources — `docs/icon.svg` (the rounded mark), `icon-apple.svg` (full bleed: iOS masks it itself and shows transparency as black) and `icon-maskable.svg` (full bleed, the mark at 78 % so it stays inside the 80 % safe-zone circle) — drawn by `scripts/icons.mjs` with sharp installed on the spot (`npm i --no-save --no-package-lock sharp`, never in `package.json`: no dependency, and CI would pay a native install), plus `docs/manifest.webmanifest` with relative paths (the site lives under `/metube-extension/`) and `display: browser`, because a documentation page has no state of its own to open on and belongs in a tab. The old `icon-128.png` (128 px with alpha, declared as the touch icon: what iOS framed in black) is gone; `tests/site.test.mjs` holds the set. C17, the website's font: Instrument Sans is self-hosted in `docs/fonts/` — the two latin variable woff2 files (upright and italic, weights 400 to 700, from `@fontsource-variable/instrument-sans` 5.3.0) with their SIL OFL licence, which must travel with the files and does since `docs/` is published whole — declared by `@font-face` at the top of `site.css` (`format('woff2-variations')`, then the same file as plain `woff2` for a browser that ignores that name) and preloaded from the head; the Google Fonts `<link>` and its two preconnects are gone. **A page load now contacts no third party**: only GitHub, the host, and `api.github.com` for the latest release's number on the download button. C17, the legal notice: a section at the foot of the page (`#legal`, linked from the footer), facts only, copied from Versus's notice where they are the same — publisher Steeve Pommier as a private individual, host GitHub Pages with GitHub, Inc.'s address, no audience measurement (the page loads no tracker, measured on its resources; the API call and the language kept in local storage are said), the MIT licence and the font's OFL. No e-mail is published anywhere in this repository, so the contact is the repository's issues; never invent one. A tracker added one day rewrites the notice in the same commit. **How to apply**: a new rule to disable goes in `biome.json` with its reason in this entry; bump Biome in `ci.yml`, `CLAUDE.md` and the README together; after a change to a source SVG, rerun the generator and commit the PNGs.
- 2026-10-21 — **Dependabot follows C20** (`second-brain#115`): monthly, 7-day cooldown (30 for an npm major), the actions in one `actions` group, an npm block with `minor-and-patch` and `security` groups and a limit of 3. **Why the npm block with no dependency**: `portfolio-check` F2 wants `minor-and-patch:` wherever a `package.json` exists, and a package added one day is then paced like the rest. No family group, no `ignore` (no `@types/node`, no Dockerfile, the old file had none). Biome is not seen by Dependabot (npx at an exact version): bump it by hand in `ci.yml`, `CLAUDE.md` and the README. **How to apply**: a red Dependabot PR is never merged nor left open — fix the repo in its own PR, or hold the version with a commented `ignore` and close it; never push to Dependabot's branch; no auto-merge.
- 2026-10-22 — **`docs/llms.txt` is a static, hand-written file** (C17, attribute J2 of the portfolio audit): there is no build step and no single source the page is generated from — the English lives in `index.html`'s markup — so generating it would mean a script parsing the page, more drift risk than the file itself. It says only what the README and the page say (what the extension does, the unpacked zip install, the permissions promise), in English (the site's default language), and links the page's sections by anchor, the legal notice, the latest release, the changelog, the README, the repository and its issues — no external link (MeTube is named, not linked), so the test can check every one. `tests/site.test.mjs` holds its llmstxt.org shape and fails on an anchor with no `id` on the page, a missing file, or any link outside the site and the repository. Not linked from the page nor listed anywhere (the site has no `robots.txt` or sitemap); GitHub Pages serves it as `text/plain`. **How to apply**: a section renamed, added or removed on the page, or a change to what the extension does, its install or its permissions, updates `llms.txt` in the same commit.

## Traps

- 2026-09-29 — **An unpacked extension's ID comes from its folder path.** Loading an update from another folder installs a second copy without the settings; the README and the release notes say to unzip over the same folder.
- 2026-09-29 — **Chrome's version format** is 1 to 4 integers from 0 to 65535 with no leading zeros; `1.0.0-beta`, `01.2` and `70000` are refused by `build.sh` before anything is built. The Web Store also refuses a version that is not higher than the last.
- 2026-10-17 — **`docs/` is published whole**, so nothing private or internal goes there; that is why the agent memory lives in `memory/`.
- 2026-10-19 — **`docs/i18n.js` puts a plain space before `:` and `;`** (38 places on that day, no no-break space in the file), against the rule `CLAUDE.md` states for French texts — which `_locales/fr/messages.json` does follow; the legal notice follows the file so the page reads alike, and nothing tests it. Moving the whole file to no-break spaces is one gesture for its own commit.
- 2026-10-19 — **Biome resolves `files.includes` against the folder of its configuration file**: a `biome.json` kept outside the repo and passed with `--config-path` matched nothing ("No files were processed"), while the same file at the root checks 34 files. Trial a rule set by editing the root file, not a copy.
